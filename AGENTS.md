# AGENTS.md — Инструкции для ИИ-агентов разработки

## 1. Контекст проекта
Разрабатывается MVP университетской социальной сети с рейтинговой системой на **PHP 8.2+** (Backend REST API) и **ReactJS** (Frontend).
Ключевая цель: надежная реализация логики академического рейтинга (АР 0..1000, поминутные штрафы за дедлайны) и раздельных активностей (БУА и БОА).

## 2. Архитектурный манифест (Строгие ограничения)
1. **Слоистая архитектура:**
   - `src/web/controllers/` -> только парсинг HTTP, вызов сервисов, возврат DTO/JSON.
   - `src/services/` -> ВСЯ бизнес-логика. Никакого SQL здесь быть не может.
   - `src/core/repositories/` -> ТОЛЬКО здесь разрешены SQL-запросы (PDO / Prepared Statements).
   - `src/core/models/` -> Сущности БД и DTO (Data Transfer Objects).
2. **Никаких "слепых костылей":**
   - Категорически запрещено подавлять исключения пустыми `catch (\Throwable $e) {}`.
   - Не ставить `?? null` или проверки на `isset()` без понимания того, почему поле отсутствует.
   - Если падает внешний метод — исследуй причину через поиск по проекту, а не маскируй симптом.
3. **Чистота PHP:**
   - Все файлы начинаются с `declare(strict_types=1);`.
   - Строгая типизация параметров и возвращаемых значений методов.
   - Никаких глобальных переменных `$GLOBALS` или `$_POST` напрямую в сервисах.

## 3. Специфические бизнес-инварианты (НЕ НАРУШАТЬ)
- **Инвариант рейтинга АР:** Число $0 \le AR \le 1000$. Рейтинг не может уйти в минус. Если списание 20, а у студента 10 АР — списывается только 10.
- **Инвариант дедлайна:** Списание 20 АР происходит **раз в минуту** только если работа не сдана (`IN_PROGRESS` или `RETURNED_FOR_REVISION`) и суммарный штраф меньше `task.max_penalty_ar`.
- **Инвариант валют:** БУА и БОА — разные балансы. Их нельзя складывать в одну колонку.
- **Инвариант бюджета:** Преподаватель не может начислить больше, чем остаток его месячного лимита на группу. Проверять атомарно в транзакции.

## 4. Доступные команды сборщика и окружения
Все команды выполняются внутри Docker или через composer:

- Запуск проекта: `docker compose up -d --build`
- Выполнение миграций и сидов: `docker compose exec backend php bin/migrate_and_seed.php`
- Прогон юнит-тестов (PHPUnit): `docker compose exec backend ./vendor/bin/phpunit tests/Unit`
- Прогон E2E-тестов: `docker compose exec backend ./vendor/bin/phpunit tests/Feature`
- Запуск тикера списания штрафов вручную: `docker compose exec backend php src/core/tasks/penalty_ticker.php`

## 5. Ролевые субагенты (Инструкции для промптов)
При постановке задач агенту явно указывайте роль:
- **@Architect:** Проверяет соблюдение границ слоев (DTO -> Service -> Repository), отсутствие циклических зависимостей и SQL-инъекций.
- **@BackendDev:** Реализует конкретные методы сервисов и репозиториев строго по контрактам DTO.
- **@QA-Engineer:** Пишет граничные тесты (тестирование списания АР у 0, переполнение семестра >1000, превышение бюджета преподавателя).
- **@Reviewer:** Проверяет код перед коммитом на чистоту, соответствие PSR-12 и отсутствие костылей.

## 6. Требование к журналу `docs/agent-log.md`
После каждой завершенной фичи или исправленного бага агент ОБЯЗАН зафиксировать запись в `docs/agent-log.md`:
1. Что было поручено.
2. С какими трудностями/ошибками столкнулся агент.
3. Какое решение было принято и почему.
