# Архитектура проекта и структура каталогов (docs/spec/architecture.md)

## 1. Архитектурная карта проекта

```
├── app/                        # Ядро приложения (App)
│ ├── Http/
│ │ ├── Controllers/            # Слой представления: валидация JSON, вызов сервисов
│ │ └── Middleware/             # Промежуточные слои (CORS, JWT / Sanctum)
│ ├── Services/                 # СЕРВИСНЫЙ СЛОЙ: Вся бизнес-логика, транзакции, расчет АР
│ ├── Repositories/             # СЛОЙ ДАННЫХ: Только здесь живут запросы Eloquent/SQL
│ └── Models/                   # Доменные сущности (User, Task, Activity и т.д.)
│
├── config/                     # Конфигурационные файлы фреймворка
├── database/
│ ├── migrations/               # Схемы таблиц PostgreSQL (запуск: php artisan migrate)
│ └── seeders/                  # Сидеры начальных данных и справочников (DatabaseSeeder)
│
├── docs/                       # Документация хакатона
│ ├── agent-log.md              # Журнал работы с ИИ
│ └── spec/                     # Спецификации (requirements, architecture, tasks, api, design)
│
├── instance/                   # Каталог для пользовательских данных
│ └── uploads/                  # Сюда сохраняются файлы сданных работ студентов
│
├── resources/                  # Ресурсы фронтенда
│ └── css/                      # Стили и дизайн-токены (tokens.css)
│
├── routes/
│ ├── api.php                   # Маршруты REST API
│ └── console.php               # Расписание воркеров (Schedule: списание 20 АР/мин)
│
└── tests/                      # Автотесты (юнит-тесты ядра и сквозные тесты API)
```

## 2. Архитектурные правила

1. **Запрет SQL вне репозиториев:** Ни Контроллер, ни Сервис не имеют права выполнять прямые SQL-запросы (`SELECT`, `INSERT`, `UPDATE`, `DELETE`).
2. **Изоляция бизнес-правил:** Контроллеры не содержат формул расчета рейтинга и проверок прав на начисление баллов — они лишь делегируют выполнение соответствующему Сервису.
3. **Атомарность операций с баллами:** Любое изменение рейтинга или баланса (списание АР за дедлайн, начисление БОА) обязано производиться внутри базы данных атомарно с фиксацией записи в журнале аудита транзакций.
4. **Использование репозиториев:** Только внутри сервисов разрешено обращаться к репозиториям.
